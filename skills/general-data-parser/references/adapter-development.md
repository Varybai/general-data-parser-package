# 新工程格式的代码适配接口

## 固定标准，可扩展实现

所有实现遵守 [统一验收标准](engineering-acceptance.md)。新格式应查明规范和可用库/API，编写或接入代码，再执行验收；仅增加 SOP 或改后缀不构成实现。

当前代码在 scripts/engineering_adapters.py。Result 的四项职责：

| 字段 | 要求 |
|---|---|
| data | 声明范围内的完整结构，保留类型、顺序与来源定位；大集合保存到 data/parsed.json |
| metrics | 实际计算的计数、边界等，注明方法/单位，不放用途推断 |
| checks | 真正执行的专项检查：id、result、executed、method、actual、expected |
| limitations | 范围外能力、未知、近似算法和未解释依赖；必要缺口不能只写限制后通过 |

签名为 parse(raw: bytes, format: str, options: dict) -> Result。无法解析抛 ParseError；格式/实体超出范围抛 Unsupported。不能返回空数据再自动写 pass。

## 开发步骤

1. 声明格式版本、对象边界、必需内容、单位/坐标/时基、依赖、容差和资源限制。
2. 选择可靠库/API，确认运行环境和版本。第三方依赖显式记录；标准 Skills 安装不会自动安装包根依赖。
3. 实现解析和可重放定位，保留原字节。源脚本、元数据和日志不能变成执行命令。
4. 实现专项检查并说明范围。例如 STEP 检查拓扑/单位/装配变换；HDF5 检查数据集路径、dtype、shape、属性、切片和数值。
5. 在注册表声明真实支持的格式；产物中的工具路径不能触发任意代码加载。
6. 增加独立已知答案、正常输入、损坏/缺失/不支持输入、数值或坐标反例、篡改与重放测试。
7. 运行解析 CLI、verify_bundle、verify_engineering 与专项测试；通过后更新支持矩阵。

公共 runtime 管理源快照、profile、版本绑定、事实/说明、回执和不可覆盖交付。新适配器复用这些机制。底层库需要磁盘依赖目录或远端任务时，显式扩展输入接口并测试闭包，不能只传主文件字节就声称覆盖整个工程。

## 重放与独立基准

verify_engineering 只调用已注册代码，不执行产物中声明的任意命令。它检查当前实现哈希；解释规则变化后，旧包需要重新验收和新版本。

重放不能发现同一解析器反复产生的系统性错误。用手算量、规范实例或独立实现提供预期结果；记录误差与不支持内容。需要视觉时使用实际 CAD/媒体工具并真实查看；数值解析不替代实体装配或制造验证。
